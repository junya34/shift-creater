# Shift Creator Pro
> **15分単位の直感的なドラッグ操作UIと、労務管理・平準化アルゴリズムを搭載した「完全サーバーレス（SPA）」自動シフト生成システム**

「誰でも簡単に、複雑な勤務条件と労働基準を満たしたシフトを作れること」を目指して開発された、バニラテクノロジー（HTML/CSS/JS）のみで構築されたシングルページアプリケーション (SPA) です。

技術的な完成度（ゼロ・ディペンデンシー設計、フロントエンド最適化、ヒューリスティック探索）に加え、「店舗・事業所の管理コスト削減」「労務違反リスクの完全回避」「人件費の最適化」といったビジネス上の課題解決（ROIの最大化）を強く意識した設計になっています。

---

## ビジネス価値と導入メリット (Business Value)

本システムは、現場のマネージャー（管理者）と現場スタッフ双方のペインポイント（痛み）を解消し、具体的な経営改善効果（ROI）をもたらします。

### 主要なビジネスインパクト

#### 1. 管理業務コスト（人件費・時間）の劇的な削減
* **課題**: 毎月のスタッフの希望収集、条件のすり合わせ、シフト表の作成・調整に、管理者が毎月10時間以上を費やしている。
* **解決**: 15分単位で直感的に入力できるスタッフ用UIと、ボタンひとつで数秒でアサインを完了する自動生成エンジンを搭載。シフト作成にかかる時間を**最大90%削減**します。

#### 2. 労務管理コンプライアンス（法規制遵守）の完全自動化
* **課題**: 労働基準法などの法規制（最大労働時間制限、所定の休憩時間挿入）の手動チェックが漏れ、労務違反や是正勧告のリスクが常につきまとう。
* **解決**: アルゴリズムが「1日最大8時間」「6時間以上の勤務への自動休憩アサイン」をシステムレベルで強制適用。**意図しない労務違反リスクを100%回避**します。

#### 3. 適正アサインによる人件費（過剰配置）の最適化
* **課題**: 忙しい時間帯にスタッフが足りず、暇な時間帯にスタッフが過剰に配置されてしまい、人件費が無駄になっている。
* **解決**: スロット単位（15分刻み）の必要オペレーション人数に基づき最適化。過剰なアサインには自動生成アルゴリズムがペナルティスコアを課してアサインを抑制するため、**無駄な人件費の発生を自動防衛**します。

#### 4. スタッフの満足度（定着率）向上と公平性の担保
* **課題**: シフトの割り振りが特定のスタッフに偏り、不満や早期離職につながる。
* **解決**: 累計勤務時間をトラッキングし、労働時間を平準化するアルゴリズムを内蔵。公平なシフト割当を実現し、**従業員の定着率（エンゲージメント）を向上**させます。

#### 5. 初期費用・ランニングコスト・インフラTCOの極小化 (Total Cost of Ownership)
* **課題**: クラウド型シフト管理サービスは月額課金（スタッフ数に応じた従量課金）が発生し、長期的なシステムコスト負担が大きい。また、機密情報（スタッフの個人情報や勤務状況）のクラウド保存への懸念。
* **解決**: 完全なクライアントサイドSPA（LocalStorage保存）のため、**サーバーインフラ維持費ゼロ、月額使用料ゼロ**で動作可能。データが外部サーバーへ送信されないため、情報漏洩リスクもありません。

## 主な機能

### 1. グラスモーフィズムを採用したプレミアムUI/UX
- 洗練されたライトテーマを基調とし、モダンなグラスモーフィズム（すりガラス効果）を取り入れたダッシュボードデザイン。
- スマートフォンやタブレットを意識した美しいレスポンシブ・サイドバーとトランジションアニメーション。

### 2. 15分単位のドラッグ＆セレクト・カレンダー
- マウスドラッグでなぞるだけで、直感的に勤務可能時間を選択・解除できる独自開発のタイムラインUI。
- 終日選択・一括クリアボタンを備え、スタッフ側のデータ入力コストを極限まで削減。

### 3. 労務ルール対応・自動シフト生成アルゴリズム (Heuristic Engine)
- **労務ルールの自動厳守**: 
  - 1日の労働時間は「最低30分（2スロット）〜最大8時間（32スロット）」。
  - 実働「6時間以上」のシフトに対し、適切な時間帯（出勤2時間後〜退勤1時間前）に自動的に「45分（3スロット）」の休憩を動的挿入。
- **労働負担の平準化**: スタッフごとの当月累計勤務時間をトラッキング。労働時間の少ないスタッフから優先してシフトに割り当てることで、不公平感のないシフトを自動生成。
- **ブレンド・ランダム性**: 生成ごとにわずかなランダム要素を加えることで、「再生成」を押すたびに異なるパターンの実用的なシフトを提案。

### 4. リアルタイム要員不足検知 & レポート
- 曜日ごとの「必要オペレーション人数」と「実際の配置人数」を毎スロット（15分単位）比較し、不足している箇所を赤くハイライト警告。
- 生成完了時、不足している日付・時間帯・人数をリストアップした **「要員不足レポート」を自動構築**。

### 5. A4横向きに完全最適化されたPDF出力・印刷
- ブラウザの印刷機能（`window.print()`）をオーバーライドし、印刷専用CSSを適用。
- サイドバーや操作ボタンなどの不要なUIを隠し、スクロールなしで綺麗にA4横サイズに収まる美しいシフト表を瞬時にPDF出力可能。

## 技術スタックと選定理由

| 技術 | 選定理由 |
| :--- | :--- |
| **HTML5** | セマンティックなマークアップによるSEO・アクセシビリティの考慮と、クリーンな骨組み。 |
| **Vanilla CSS3** | CSS変数を活用した一元的なカラーシステムとテーマ管理。ブラウザの描画負荷を最小限に抑えるため、重いフレームワークは不採用。 |
| **Vanilla JavaScript (ES6)** | ライブラリに依存しない純粋なJavaScript。IIFE（即時実行関数）を採用し、グローバル汚染を防ぐ疎結合なモジュール設計。 |
| **LocalStorage API** | 完全なサーバーレスSPAを実現するため、ブラウザローカルでの軽量なデータ永続化を採用。 |

## アーキテクチャとディレクトリ構造

プロジェクトは関心の分離（SoC）を徹底し、役割ごとにファイルが厳密に分けられています。

```text
shift-creater/
├── index.html        # エントリーポイント。セマンティックなHTML5による骨組み
├── css/
│   └── style.css     # UIのコアスタイル。レスポンシブ、PDF印刷用クエリ、アニメーションを網羅
└── js/
    ├── app.js        # アプリケーションのハブ。初期化、ルーティング、イベントリスナーの集中管理
    ├── store.js      # データ永続化レイヤー。LocalStorageのI/O、フォーマット、定数定義
    ├── ui.js         # レンダリングレイヤー。カレンダー、入力グリッド、シフト表のDOM描画
    └── scheduler.js  # ビジネスロジック。ヒューリスティック探索による自動シフト生成エンジン
```

## 技術的なアプローチと最適化手法

### 1. ヒューリスティック自動生成のアルゴリズム
`js/scheduler.js` に実装されているアルゴリズムは、以下の優先順位（制約）に基づいて動作します：

1. **希望の合致**: スタッフの提出した希望時間内でのみアサイン。
2. **労働平準化**: 月間勤務合計時間が少ないスタッフを優先ソート。
3. **スコアリング評価**: シフトの長さと必要オペ人数の充足度をスロットごとに加減点して評価（過剰アサインにはペナルティを課すことで、人件費の無駄を自動削減）。
4. **休憩の自動挿入**: 6時間以上の連続勤務が発生する際、条件を満たすスリットへ3スロット分の休憩を自動で挟み込み、オペレーション要員からその時間だけ除外。

### 2. パフォーマンス最適化
バニラJS特有の「大量DOM生成時のレンダリングボトルネック」を解消するため、以下の最適化を施しています：

- **DocumentFragmentの導入**: カレンダーやグリッドを描画する際、ループ内で直接DOMツリーに追加（Append）せず、仮想的な `DocumentFragment` に蓄積。ループ終了時に一括アタッチすることで、リフローとリペイントの発生回数を1回に抑えています。
- **DOMクエリのキャッシュ化**: ユーザーが操作するたびに実行されていた `document.querySelectorAll` を、初期化時にキャッシュ（定数化）。DOM検索にかかる計算量を $O(N)$ から $O(1)$ へ削減しました。
- **静的処理の事前キャッシュ**: タイムスロット用ラベル配列など、実行中に値が変わらないデータは初回生成時に結果をキャッシュし、再計算を防いでいます。
- **リソースのプリコネクト（Preconnect）**: Google Fonts などの外部Webフォントの参照に対し、HTMLヘッド内に `preconnect` を定義。DNS解決やTLSハンドシェイクを事前に行うことで、初期読み込み時間を短縮しました。

## 動作確認・デプロイ方法

### ローカルでの即時実行
ビルド手順や `npm install` などの環境構築は一切不要です。
1. 本リポジトリをクローンまたはダウンロードします。
2. `index.html` を任意のブラウザ（Chrome, Edge, Safari, Firefox等）でダブルクリックして開いてください。

### GitHub Pages へのデプロイ
1. GitHubにリポジトリを作成し、コードをプッシュします。
2. リポジトリの `Settings` -> `Pages` に移動します。
3. Sourceに `Deploy from a branch` を選択し、`main`（または `master`）ブランチを設定して保存します。
4. 数分で、公開用のポートフォリオURLが自動生成されます。
